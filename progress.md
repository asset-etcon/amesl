  ```
  max_connections                 20
  - superuser_reserved            -3   (avnadmin is NOT a superuser, so these are unreachable)
  - Aiven internal backends      -12   (TimescaleDB, pg_failover_slots, pg_cron, unnamed slots)
  - Aiven management-agent        -1   (held open by Aiven)
  ------------------------------------
  available for this application    4
  ```
  `PG_POOL_MAX` was **5**, so a *single* process could exhaust the server unaided. A 40-request burst produced **17 × 5xx**.   - Same burst after the fix: **40/40 ok, 0 server errors**, `amesl` connections capped at 2 and reclaimed to 0 after the idle timeout. 4 connections per 20 is the ceiling for this plan — use `PG_POOL_MAX=1` if you ever run more than ~2 concurrent Vercel instances, or raise the Aiven plan.

## News CMS + Sitewide SEO
- **Schema** — `news_categories` and `news_posts` added to `sql/schema.sql` and `db/schema.ts`, applied to the live Aiven DB (idempotent, re-ran cleanly: 7 indexes, 1 trigger, no duplicates). `publish_at timestamptz` is nullable: NULL = publish immediately, a future value holds the post back. A partial index `news_posts_published_idx on (publish_at desc, created_at desc) where status='published'` serves the public listing. Also fixed a latent bug: `hero_slides` had a `set_updated_at` trigger assigning `new.updated_at` on a table that never declared that column.
- **Started empty, as requested** — no seed rows. `news_posts` and `news_categories` are both 0 rows. `/news` renders an empty-state message rather than placeholder content.
- **`lib/news.ts` is the single source of truth for visibility.** `publishedNewsWhere()` = `status='published' AND (publish_at IS NULL OR publish_at <= now())`. Every public read (listing, post page, category page, homepage band, sitemap, OG image) uses it; `isNewsVisible()` is the JS mirror used by the admin table. Never re-derive this rule inline — the classic failure is a scheduled post leaking early.
- **Scheduling ordering bug (found and fixed by test).** `orderBy(desc(publish_at), desc(created_at))` was wrong: Postgres sorts **NULLs first** under `DESC`, so every never-scheduled post outranked every scheduled one regardless of age. `newsOrder` now uses `desc(coalesce(publish_at, created_at))`, which makes an immediate post sort by its creation date and interleave correctly with dated posts.
- **Security baseline (pre-existing issues, now fixed):**
  - `lib/session.ts` silently fell back to the public constant `"insecure-dev-secret-change-me"`, so a production deploy missing `SESSION_SECRET` would accept forged session cookies with nothing in the logs. Added `assertSessionSecret()`, which throws in production only (dev keeps the placeholder).
  - `loginAction` had **no rate limiting** and returned two different messages, so it confirmed which emails were registered. Now: 10 attempts/15 min per client fingerprint, 8/15 min per email; a single `GENERIC_LOGIN_ERROR`; and an unknown email still runs a bcrypt compare against `TIMING_EQUALIZER_HASH` so the response time does not leak account existence.
  - `uploadAssetAction` called `requireRole()` **inside** its `try`, so the `redirect()` thrown for an unauthenticated caller was caught and returned as `{ok:false, error:"NEXT_REDIRECT…"}` — the login redirect was swallowed and a raw message reached the browser. Auth is now hoisted above the `try`.
  - Note: this same `requireRole`-inside-`try` shape exists in **all 9 pre-existing admin action files** (`brands`, `categories`, `hero-slides`, `homepage`, `media`, `products`, `quotes`, `settings`, `users`). It fails *closed* (the throw precedes any mutation), so it is a correctness and information-disclosure issue, **not** a privilege bypass. New `lib/action-guard.ts` (`rethrowIfControlFlow`, `actionErrorMessage`) fixes it; the new news actions use it, but retrofitting the 9 older files is still outstanding.
- **`lib/sanitize.ts` (new, `sanitize-html`)** — allowlist for TipTap output. Strips script/iframe/style/object/embed/form/meta/svg/img, all `on*` handlers, `javascript:`/`data:` URLs, and filters `style` down to `text-align`/`font-weight`/`font-style`/`text-decoration`. Cover images go through `normaliseCoverImageUrl()`, which accepts only `/…` paths and `http(s)`.

For the current deploy: `406fe8ed73363dbdca2c8f0d167ab059b13becb69d`. Re-scrape after every deploy — it changes.
